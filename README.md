# OpsPilot

AI-powered incident response and operations platform. OpsPilot gives on-call engineers a single place to triage incidents, draft stakeholder updates, generate postmortem documents, and track every action with a human-approval audit trail — all backed by Claude.

## Features

- **Incident dashboard** — browse open and resolved incidents with severity, status, and affected services
- **AI analysis** — LLM-backed root cause analysis with recommended runbooks and escalation targets (falls back to deterministic logic when no API key is set)
- **Stakeholder update drafting** — audience-aware update text generated by Claude, ready to approve or reject
- **Postmortem generation** — structured postmortem draft (title, timeline, root cause, follow-ups) produced by Claude
- **Human approval workflow** — approve or reject any AI-generated artifact; all decisions are persisted
- **Audit trail** — every generated artifact and approval/rejection is logged per-incident

## Prerequisites

- Python 3.11+  
- Node.js 18+ and npm  
- An `ANTHROPIC_API_KEY` (required for LLM features; the app runs in fallback mode without it)

## Local run — Windows PowerShell

Each service runs in its own terminal. Start them in any order; the web UI just needs the API to be reachable.

### 1. One-time setup

```powershell
# From the repo root
Copy-Item .env.example .env
# Open .env and paste your ANTHROPIC_API_KEY

# Install Python dependencies
cd apps\api
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
cd ..\..

cd apps\mcp-server
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
cd ..\..

# Install Node dependencies
cd apps\web
npm install
cd ..\..
```

### 2. Terminal 1 — API

```powershell
cd apps\api
.\.venv\Scripts\Activate.ps1
python -m uvicorn main:app --reload --host 0.0.0.0 --port 8000
```

Verify: http://localhost:8000/health

### 3. Terminal 2 — Web UI

```powershell
cd apps\web
npm run dev
```

Verify: http://localhost:3000

### 4. Terminal 3 — MCP server (optional, for MCP Inspector / AI agent use)

```powershell
cd apps\mcp-server
.\.venv\Scripts\Activate.ps1
mcp dev .\main.py
```

The MCP Inspector opens at http://localhost:5173 (printed in the terminal).

## Local run — Unix / macOS / Git Bash

```bash
cp .env.example .env
make install
make dev-api      # terminal 1

make dev-mcp      # terminal 3
```

## Docker (any OS)

### Prerequisites
- Docker Desktop (or Docker Engine + Compose plugin) installed and running

### Steps

**Bash / macOS / Linux:**
```bash
cp .env.example .env
# Open .env and set ANTHROPIC_API_KEY=sk-ant-...
docker compose up --build
```

**Windows PowerShell:**
```powershell
Copy-Item .env.example .env
# Open .env and set ANTHROPIC_API_KEY=sk-ant-...
docker compose up --build
```

All three services build and start in one command. The first build takes a few minutes; subsequent starts are fast (`docker compose up` without `--build`).

### Expected URLs once running

| Service    | URL                          | Notes                        |
|------------|------------------------------|------------------------------|
| Web UI     | http://localhost:3000        | Main dashboard               |
| API        | http://localhost:8000        |                              |
| API health | http://localhost:8000/health | Returns `{"status":"ok",...}`|
| API docs   | http://localhost:8000/docs   | Swagger UI                   |
| MCP server | http://localhost:8001        | SSE transport in Docker      |

### Stopping

```bash
docker compose down
```

### Notes

- `ANTHROPIC_API_KEY` is optional — all LLM features fall back to deterministic output if it is missing or invalid.
- `NEXT_PUBLIC_API_URL` defaults to `http://localhost:8000`. The web UI calls the API from the browser, so this must be reachable from the machine running the browser. Change it in `.env` if running Docker on a remote host.
- Audit events are written to `data/audit/` on your host machine (the `data/` directory is mounted read-write into the API container).

## Suggested demo flow

Use incident `INC-001` (pre-seeded) to walk through the full workflow:

1. **Open incident** — navigate to http://localhost:3000 and click on INC-001 to view its details (severity, affected services, summary).
2. **Analyze incident** — click "Analyze" to trigger `GET /incidents/INC-001/analysis`. Claude identifies the likely root cause, recommends a runbook, and lists escalation targets.
3. **Draft stakeholder update** — click "Stakeholder Update" to trigger `GET /incidents/INC-001/stakeholder-update`. Claude drafts audience-appropriate update text and next steps.
4. **Generate postmortem** — click "Postmortem" to trigger `GET /incidents/INC-001/postmortem-draft`. Claude produces a structured postmortem with timeline, root cause, and follow-up actions.
5. **Approve or reject** — use the Approve / Reject buttons on any draft. Each decision is recorded via `POST /incidents/INC-001/{artifact}/approve` or `/reject`.
6. **Load audit history** — click "Audit Trail" to call `GET /incidents/INC-001/audit` and see every generated artifact and human decision in chronological order.

> All LLM steps fall back to deterministic output automatically if `ANTHROPIC_API_KEY` is not set or the API call fails, so the demo works offline.
